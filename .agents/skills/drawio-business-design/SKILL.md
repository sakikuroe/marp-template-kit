# draw.io 業務図のデザイン

統一するのは配色、書体、線、角丸、影の使い方。図種・構図・情報量は、内容と読み手に合わせて設計する。既存の作例を模写する必要はない。
ユーザーの指定を優先する。数値はこの見た目を再現する出発点であり、新しい図の構図や表現を制限するものではない。

数値はdraw.ioの図上座標。PNGの描画倍率に合わせて設計値を倍にしない。

## 配色・線・書体

| 要素 | 出発点 | 使い方 |
| --- | --- | --- |
| 図形の塗り | `#ffffff` | 透明背景でも図形の内部は白 |
| 本文・主要線 | `#171717` | 主要輪郭と接続は線幅1.3程度 |
| 補助境界 | `#b5b5b5`、線幅1 | 領域や控えめな要素 |
| 軽い罫線 | `#dddddd`、線幅1 | 情報の区切りに必要な箇所だけ |
| 注意喚起の色 | 濃淡のある低彩度の色 | 例：赤のアクセント`#9b6661`、文字`#824d48`、薄い背景`#fbf3f2`。使う面積で強さを調整 |
| 通常文字 | `GenEi M Gothic v2 Medium` | 実体はMedium（500） |
| 見出し・重要な区画名 | `GenEi M Gothic v2`＋`fontStyle=1` | 実体はBold（700） |
| 通常の文字サイズ | 18～22程度 | 掲載先での読みやすさを確認 |
| 補足・線のラベル | 16～18程度 | 小さすぎる場合は図の分割や配置を検討 |

通常の情報と例外を色分けするときも、色に対応する文字や記号を残す。すべてを色分けしたり、色を変えるついでに同じ役割の図形の形まで変えたりしない。

名前だけ指定して別書体へ置換された画像を完成としない。このリポジトリの描画スクリプトは実フォントを使い、標準でSVGにも埋め込む。VS Codeのdraw.io表示にはホスト側にもフォントが必要。
別の書体を指定された場合は字幅と改行を再確認する。フォントファイルをスキルへ同梱しない。

## 角丸と影

通常の箱は`rounded=1;absoluteArcSize=1;arcSize=20`を出発点とする。長方形の出力SVGでは半径約10になる。大きい図形ほど角丸が大きくなる設定にしない。
判断の菱形にも同じ設定を明示し、実際の頂点の丸みを画像で見る。小さな部品には小さな半径を選び、同じ役割の要素で揃える。記法上の形状・開口部は維持する。直角を選ぶ場合も、同じ役割の要素では揃える。

黒い輪郭の内容ノードは`shadow=1`で控えめな影を付ける。薄い灰色の輪郭の要素は`shadow=0`。領域境界、罫線、小さな記号にも影を付けない。
影の有無を、ページごとの気分や描画の都合で変えない。同じ役割・同じ強調度では、同じ輪郭・角・影にする。

通常の箱のスタイル例：

```text
rounded=1;absoluteArcSize=1;arcSize=20;whiteSpace=wrap;html=0;fillColor=#ffffff;strokeColor=#171717;strokeWidth=1.3;shadow=1;fontFamily=GenEi M Gothic v2 Medium;fontColor=#171717;fontSize=20;
```

影を付ける形では、設定だけでなく出力SVGの影と外周の切れを確認する。透明画像は白系の背景に重ねて確認する。

## 余白と接続の確認

- **文字と輪郭：** 日本語1文字を文字サイズ分、ASCIIを約半分として初期の幅を見積もる。内側余白は16～20程度から始め、実フォントで確認する。角丸や菱形の狭い部分にも文字が触れていないか見る。
- **文字量：** 収まらないときは、意味の切れ目での改行、箱の拡張、配置変更を検討する。一律の文字縮小で解決しない。語の途中で分断しない。
- **まとまり：** 近い要素が関連して見える距離にする。独立したまとまりの間は、まとまり内部より広く取る。全ての隙間を同じ値にしない。
- **整列：** 同じ役割の上端、中心軸、文字の基準位置を揃える。行数の違う要素の下端まで無理に揃えて、意味のない空白を増やさない。
- **接続：** 箱だけでなく線とラベルの通り道も確保する。線が無関係な箱や文字を横切らず、どこへ接続するか追えるか確認する。交差が多いなら経由点を増やす前に配置を見直す。
- **曲がり方：** 短い接続は直線にする。迂回には曲線や小さな丸みを使い、鋭い曲がりや意味のない斜め線を残さない。記法上必要な線の形は保つ。
- **ラベル：** 矢印の先端、輪郭、交点から離し、所属する線が明らかな場所へ置く。白いラベル背景は必要なときにだけ使う。
- **外周：** 端だけ大きな空白が残っていないか、影や文字が出力の範囲で切れていないか見る。自然な内容の範囲へ出力し、周囲余白は16程度から調整する。

全体を掲載サイズで見る確認と、局所を拡大する確認の両方を行う。SVGとPNGで文字、太さ、配置が揃っているか確認する。
複数図を一覧で見るときも、図ごとの情報量や構図は揃えず、共通の見た目が揃っているかを見る。

## 内容と配置は図ごとに判断する

読み手に何を伝えるか、掲載先でどの程度の大きさで読むかを踏まえて構図を選ぶ。
全図を同じ「見出し・補足見出し・図・フッター」にしない。名称、凡例、前提などは必要性を判断し、その情報が効く場所へ置く。
説明を削る前に、配置で改善できないか考える。判断に必要な条件や制約を見栄えのために失わない。
日本語は役割に合った自然な表現にする。助詞を省いた断片や抽象語の列挙で、主体・対象・条件を曖昧にしない。文章の句読点は「、」「。」を使い、識別子や数値の記号は保つ。

## 描画して確かめる

このリポジトリでは`./scripts/render-diagram.sh <入力.drawio>`でSVG・PNGを生成する。標準の出力先は`out/diagrams/`。試作は`--output out/previews/<作業名>`へ出し、更新には`--force`を使う。
他の環境では利用可能なdraw.ioの描画手段を使う。別の描画基盤をこのスキルのために新設する必要はない。

1. 全体を最終的な掲載サイズで見て、読み順・情報の強弱・文字の大きさを確認する。
2. 密集箇所、長い文字、端の要素、接続の交差を拡大して、余白・欠け・重なりを確認する。
3. 複数の図を扱う場合は並べて見て、同じ役割の輪郭・角・影・書体が揃っているか確認する。
4. 修正した要素と、移動や寸法変更で影響を受けた周囲を描画し直す。

XMLの設定だけで完成と判断しない。SVGとPNGの実際の字形、角、影、配置を確認する。画像を確認できない場合は、その制限を報告する。
